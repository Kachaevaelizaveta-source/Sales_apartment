# Инструкция по устройству и правкам воркбука DataLens

## Файлы

- `Продажи ЖК_1.json` — JSON-экспорт воркбука DataLens.
- `Продажи ЖК, март–сентябрь 2026.xlsx` — файловый источник, лист `full`.
- `opencode.json` — служебная конфигурация OpenCode, не часть воркбука.

Инструкция составлена по локальному JSON и Excel; внешние спецификации не использовались.

## Реальная структура экспорта

Корень JSON:

```text
{
  "export": {
    "version": "v1",
    "entries": {
      "connection": { "3": { "connection": ... } },
      "dataset": { "2": { "dataset": ... } },
      "widget": { "1": { "widget": ... } },
      "dash": { "0": { "dash": ... } }
    }
  },
  "hash": "..."
}
```

### Связи объектов

1. `connection["3"]` подключает Excel-файл и имеет `workbook_id` и `sources[].id`.
2. `dataset["2"]` — датасет `Продажи ЖК — сделки`; его источник ссылается на подключение через `connection_id: "3"` и `origin_source_id`.
3. В `dataset["2"].dataset.sources[0].raw_schema` лежат 15 исходных полей.
4. В `dataset["2"].dataset.result_schema` лежат поля, доступные чартам: исходные поля и вычисляемые формулы. У каждого поля есть стабильный `guid`; ссылки в формулах используют именно guid-поле.
5. `widget["1"]` — чарт типа `d3_wizard_node`. Настройки находятся в `widget.data.shared`:
   - `datasetsIds` — используемые датасеты;
   - `visualization` — тип графика и его `placeholders`;
   - `colors`, `shapes`, `labels`, `tooltips` — поля визуальных кодировок;
   - `datasetsPartialFields` — сокращённый список полей для виджета.
6. `dash["0"]` — дашборд. В `tabs[].items[]` лежит элемент-виджет, а `data.tabs[].chartId: "1"` связывает дашборд с `widget["1"]`.

## Поля уровня сделки

Источник `full` содержит одну строку на сделку/квартиру и поля:

| Исходное имя | Тип | Роль |
|---|---|---|
| `kvartira` | string | идентификатор квартиры/сделки |
| `korpus` | string | корпус |
| `etazh` | integer | этаж |
| `komnat` | integer | число комнат |
| `planirovka` | string | планировка |
| `ploshchad_m2` | float | площадь |
| `tsena_za_m2_rub` | float | цена за м² |
| `stoimost_rub` | float | базовая стоимость до скидки |
| `skidka_rub` | integer | скидка в рублях |
| `summa_sdelki_rub` | float | фактическая сумма сделки |
| `menedzher` | string | менеджер |
| `data_sdelki` | datetime | дата сделки |
| `data_obrashcheniya` | datetime | дата обращения |
| `dney_v_rabote` | integer | дни от обращения до сделки |
| `vid` | string | вид |

В датасете уже есть вычисляемые поля:

- доля скидки: `skidka_rub / stoimost_rub` с защитой от нулевой стоимости;
- интервалы этажей;
- обратный скор скорости `1 / (1 + dney_v_rabote)`;
- текстовая категория продаваемости по сроку и доле скидки.

## Созданный график

В `widget["1"]` настроена пузырьковая scatter-карта **«Карта продаваемости квартир: скорость x скидка»**. В имени объекта использованы только безопасные для импорта символы:

- X: `dney_v_rabote` — дни в работе;
- Y: вычисляемая доля скидки;
- точка (`points`): `kvartira` — это принципиально фиксирует гранулярность «одна точка = одна сделка», а не агрегат по корпусу/комнатам;
- размер пузыря: `ploshchad_m2`;
- цвет: `vid`;
- форма: `komnat`;
- подсказка: квартира, вид, комнаты, корпус, этаж, планировка, площадь, цена за м², базовая стоимость, скидка, доля скидки, сумма сделки, дни в работе и дата сделки.

Интерпретация: левый нижний сектор — быстро проданные квартиры с меньшей скидкой; правый верхний — продававшиеся дольше и с большей уступкой. Размер, цвет и форма позволяют одновременно увидеть характеристики квартир и выбросы.

## Правила внесения правок

1. Не менять `export.version`, `workbook_id`, UUID подключения/источника и идентификаторы датасета без необходимости.
2. Не переименовывать исходные поля: чарт и вычисляемые формулы используют их `guid`.
3. Для показателей продаж использовать `summa_sdelki_rub` (фактическая сумма сделки), а не `stoimost_rub`.
4. Для количества сделок использовать `kvartira` как dimension с `COUNTD`, а в scatter-графике — обязательно помещать `kvartira` в `points`.
5. Не заменять поле сделки агрегированным измерением (`korpus`, `komnat`, `vid`): такие поля подходят для цвета/формы/фильтров, но не задают частицу данных.
6. Скидку анализировать в рублях и долей от `stoimost_rub`; при делении защищаться от нуля.
7. Срок продажи анализировать по `dney_v_rabote` и не показывать среднее без количества сделок.
8. При добавлении поля в чарт добавлять его с тем же `guid`, `datasetId: "2"` и согласованным `source`/`formula` из `result_schema`.
9. Сохранять JSON в UTF-8 и после правки проверять, что он снова разбирается как JSON.
10. Не выполнять форматирование или пересоздание хеша без понимания механизма импорта: верхнеуровневый `hash` в этой правке сохранён как был.
